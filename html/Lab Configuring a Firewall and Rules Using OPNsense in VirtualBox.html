OPNsense Firewall Lab — VirtualBox Environment

Course Context: Hands-on cybersecurity lab focusing on installing OPNsense in VirtualBox, configuring dual WAN/LAN interfaces, building stateful firewall rules, and validating traffic segmentation.

Lab Objectives

  • Install OPNsense within VirtualBox configured with dual network adapters: WAN (NAT) and LAN (Internal Network).
  • Configure stateful firewall rules to allow ICMP traffic and block destination websites.
  • Test network connectivity and gather empirical screenshot evidence for verification.
  • Explain how network segmentation and the Principle of Least Privilege operate in modern firewall architecture.

Software Requirements

  • Hypervisor: Oracle VirtualBox (Latest Release)
  • Firewall ISO: OPNsense Official Installation ISO
  • Documentation Reference: OPNsense System Administration Guide
  • Virtual Machine Architecture: Two active VMs (OPNsenseFirewall and a client OS such as Windows Client or Linux Workstation).

Step-by-Step Lab Setup Procedures

1. Create OPNsense Virtual Machine

In VirtualBox, select New VM. Set OS Type to BSD and Version to FreeBSD (64-bit). Allocate at least 2048 MB RAM and a 20 GB VDI dynamically allocated disk. Attach two virtual network adapters:

  • Adapter 1 (WAN): Attached to NAT (provides upstream internet exposure).
  • Adapter 2 (LAN): Attached to Internal Network named LabNet.

2. Install OPNsense & Assign Interfaces

Boot the VM from your downloaded OPNsense ISO. Follow the installer prompts to assign interface mapping: map em0 to WAN and em1 to LAN. By default, the OPNsense LAN gateway IP is set to 192.168.1.1/24.

3. Client VM Configuration

Connect your Client VM (Windows or Linux) to the same Internal Network (LabNet). Assign the client static IP 192.168.1.10/24 with default gateway 192.168.1.1 (or enable OPNsense DHCP service). Confirm web connectivity by opening a browser and reaching the WebGUI at https://192.168.1.1.

4. Configure Firewall Rules

Navigate to Firewall → Rules → LAN in the OPNsense WebGUI:

  • Create an Allow Rule for ICMP protocol (echo request/reply) to allow ping testing out to external targets.
  • Create a Block Rule for facebook.com using an IP/Domain Alias or Blocklist.
  • Click Apply Changes to enforce rule evaluation.

5. Validation & Screenshot Evidence Collection

From the client machine terminal, execute ping 8.8.8.8 to verify ICMP pass-through. Next, attempt navigating to https://facebook.com in your client browser to confirm the connection is dropped/blocked. Capture clear screenshots of: (1) OPNsense LAN Rules list, (2) successful terminal ping output, and (3) browser timeout/blocked connection page.

Lab Walkthrough — Diagnostic Commands

# Test Internet & ICMP Connectivity:
ping 8.8.8.8

# Inspect Client Network Configuration:
ipconfig /all (Windows) or ifconfig (Linux)

# OPNsense State Table Verification:
WebGUI → Firewall → Diagnostics → States

Firewall Engineering Best Practices

  • Rule Ordering: Place specific BLOCK rules above general ALLOW rules. Firewalls process rules sequentially top-to-bottom and apply the first matching rule.
  • Alias Management: Group domain names and IP addresses into Aliases (Firewall → Diagnostics → Aliases) for modular rule maintenance.
  • Logging & Auditing: Always enable logging on block rules to track unauthorized connection attempts in Firewall → Log Files → Live View.
